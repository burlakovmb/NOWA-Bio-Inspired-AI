# Issue #22 — Старость колонии в сим-секундах

English: [issue-22-colony-lifespan-sim-seconds.en.md](issue-22-colony-lifespan-sim-seconds.en.md)

Закрывает #22 (только хост демо). PR #61. Связано: [issue-39-dt-robustness.ru.md](issue-39-dt-robustness.ru.md) (частота решений vs `dt`).

Когнитивное **ядро** в `src/` (включая `src/mortality.py`) не менялось. У каждой шиншиллы по-прежнему свой `Agent` и свой `MortalitySystem`.

---

## 1. Проблема

В `Demo/Colony chinchillas` смерть от **старости** шла по `MortalitySystem.max_lifespan_steps` (`COLONY_MAX_LIFESPAN_STEPS = 20000`), потому что `max_lifespan_age_s` не задавался. Ядро тогда сравнивает **число решений**, а не биологический возраст, пока `max_lifespan_age_s` равен `None`.

Срок жизни в сим-секундах зависел от шага UI и ускорения:

| Контекст шага | Примерное модельное время при 20 000 решениях |
| --- | --- |
| Номинальный кадр 1× (`dt = 1/12` с) | ~1667 с |
| Шаг под нагрузкой (`dt = 0.25` с) | ~5000 с |

Это противоречит правилу проекта: симуляция должна оставаться корректной при любом ускорении — одна и та же особь должна умирать от старости при одном **биологическом возрасте**, а не после одного числа решений.

---

## 2. Решение и обоснование

**Решение:** задать `max_lifespan_age_s` в `MortalitySystem` каждого `ChinchillaAgent` из базы колонии и генома. По-прежнему передавать `biological_age_s=self.age` из колонийных часов (уже было). `COLONY_MAX_LIFESPAN_STEPS = 20000` оставить в `max_lifespan_steps` для снимков и нормализации индекса здоровья; ядро **не использует** поле шагов для старости, пока задан `max_lifespan_age_s`.

**Базовая константа:**

```text
COLONY_MAX_LIFESPAN_AGE_S = 15 * MATURITY_AGE_S = 13500 s
```

(`MATURITY_AGE_S = 900` в `config_colony.py`.)

**На особь:**

```text
max_lifespan_age_s = COLONY_MAX_LIFESPAN_AGE_S * genome.genes.get("lt_max_lifespan_factor", 1.0)
```

Ген `lt_max_lifespan_factor` — простой множитель (диапазон реестра **0.5..2.0**), поэтому предел старости **6750..27000** с. Без генома или при множителе **1.0** остаётся **13500** с. Новорождённые получают свой геном после кроссовера; у каждой особи свой `MortalitySystem` с пределом по её геному (после рождения cap обновляется).

**Обоснование (биология → время демо):** в неволе шиншиллы созревают примерно за 8 месяцев и в среднем живут около 10 лет — отношение ×15 между взрослой жизнью и созреванием. Демо уже отображает созревание в `MATURITY_AGE_S`, поэтому **базовый** предел старости — 15 × 900 с. Сверка с размножением: `13500 / GESTATION_S` (`GESTATION_S = 300`) даёт **45** беременностей, в пределах реальных 10–15 лет (примерно 33–49 беременностей по 111 дней). Эстральный цикл — слабее якорь: цикл в демо длиннее относительно реального ~38-дневного.

**Медиа-скрипты:** `tools/render_evolution_media.py` и `tools/render_promo_media.py` принудительно убивают через `biological_age_s=colony_scripted_old_age_s(agent)` — не ниже собственного `MortalitySystem.max_lifespan_age_s` особи — с причиной `old_age`, а не через `lived_steps =` бюджет шагов.

---

## 3. Поведение

- **Старость:** `MortalitySystem.update` регистрирует `old_age`, когда `biological_age_s >= max_lifespan_age_s` (индивидуальный предел; по умолчанию **13500** с). Число решений не ограничивает старость.
- **Раньше старости:** `exhaustion` (энергия ≤ критический порог) и `sleep_deprivation` (бодрствование ≥ критический порог) без изменений; потеря vitality при senescence без изменений.
- **Ядро на особь:** у каждой шиншиллы свой `MortalitySystem` (и полный стек NOWA); у потомства новые экземпляры с пределами по их геномам.

## 5. Последствия

- Старость наступает при **индивидуальном cap в сим-с**, независимо от скорости UI и дробления sub-tick (по умолчанию **13500** с; раньше ~1667 с при шаге `1/12` с и ~5000 с при `0.25` с при том же бюджете 20 000 решений).
- Эволюция может укорачивать или удлинять жизнь через `lt_max_lifespan_factor` (6750..27000 с) без смены базовой константы.
- Эффективная жизнь удлиняется на прежних номинальных скоростях; линии и численность тянутся, если не доминируют другие причины смерти.
- **Долг:** компонент **lifespan** аналитики роя по-прежнему нормирует среднее `lived_steps` на `max_lifespan_steps` (`colony_gui/swarm_analytics.py`), а не на `max_lifespan_age_s` — индекс здоровья может занижать «прожитую долю» относительно новых часов старости.

## 6. Открытые вопросы

| Тема | Заметки |
| --- | --- |
| ×15 vs ×22.5 взрослой жизни | Альтернативная **база** `22.5 * MATURITY_AGE_S = 20250` с (до `lt_max_lifespan_factor`) — выбор продукта / биологии |
| Доля lifespan в health-index | Согласовать знаменатель с `max_lifespan_age_s` или возрастом при смерти — последующая задача |
| Геном при save/load колонии | `ColonyStorage` не сохраняет `genome`; после загрузки особь снова с множителем 1.0 (**13500** с) — прежнее ограничение, не введено этим изменением |
