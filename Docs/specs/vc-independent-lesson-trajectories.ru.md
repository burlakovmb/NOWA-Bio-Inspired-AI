# Независимые траектории оценённых уроков тела

English: [vc-independent-lesson-trajectories.en.md](vc-independent-lesson-trajectories.en.md)

## Контракт

`nowa_body.feedback_loop.store_lesson` представляет независимое предъявление
контекста/действия/оценённого исхода. После сохранения нового эпизода и до
`Agent._record_known_outcome` назначаются:

```python
episode.trajectory_id = "vc-lesson:" + str(episode.episode_id)
episode.episode_step = 0
```

Штатный гиппокамп предоставляет уникальный среди хранимых эпизодов `episode_id`.
Производная траектория уникальна внутри ума, сохраняется с эпизодом и отделена
от штатных `traj-N`. Повторные предъявления — отдельные эпизоды. Не добавляются
счётчик, случайный выбор, поле checkpoint или API ядра. Приватный helper позволяет
провести экспериментальный контроль с отключённой разметкой.

Это относится ко всем вызовам `store_lesson`: наставническому
`BusinessAgentRuntime.teach`, оценённым одобрениям/отказам, урокам блокировки
лимита и строгого связывания. Урок описывает собственную оценённую ситуацию,
а не продолжает последнюю траекторию бодрствования. Меняется будущее обучение
тела; загрузка старого ума не мигрирует его эпизоды.

## Причина

Сон распределяет причинный вклад внутри каждой траектории. Без её метаданных
независимые уроки получают общую старую группу пустого id и позиции выборки.
Сортировка timestamps и повторённые ссылки могут вывести несвязанные уроки
за окно причинного вклада. Явная независимая траектория с шагом `0` даёт уроку
глубину `0`, в том числе при повторах в replay, без изменения универсального
ядра или его правил воспроизведения.

## Сохраняемое поведение

- Публичные сигнатуры `store_lesson` и `teach`, непрерывная награда/ограничение,
  интенсивность, контекст, действие, последствие и аргументы известного исхода.
- Прежние `terminal=False` и self-bootstrap. Идентичность траектории сама по
  себе не меняет terminal-семантику TD.
- Штатные `Agent._trajectory_id`, `_trajectory_seq`, `_trajectory_step` и
  `_trajectory_closed`. Тело не вызывает `_mark_transition_trajectory`.
- Устойчивое обучение через `Agent.sleep()`; исходы наяву входят только в
  ограниченный labile-слой. Метаданные — состояние эпизода, не устойчивое обучение.
- Неоценённые вызовы `_store_episode` и seeders роли. Их старая семантика прежняя.
- Архивные checkpoints и существующие эпизоды. Переразметки и миграции при загрузке
  нет. Новые и старые эпизоды могут сосуществовать; старые исключения допустимы.
- Ядро `src/`, корневые `tests/`, платформа `src/mcp_body/` и фабрика.

## Совместимость и сохранение

Штатный `Experience` поддерживает оба записываемых сериализуемых поля. Тесты
настоящего ядра обязаны проверять разметку каждого нового оценённого урока
до регистрации. Не придумывать id при отсутствующем/пустом `episode_id`.
Поддерживаемые простые заглушки по-прежнему сохраняют эпизоды; отсутствие или
запрет записи метаданных не ломает прежний путь хранения. Если назначение нельзя
завершить, не оставлять вводящую в заблуждение частичную разметку там, где
интерфейс атрибутов объекта позволяет восстановление. Ошибку самой регистрации
известного исхода не проглатывать.

VC `save_mind`/`load_mind` сохраняет оба поля без нового sidecar. Штатный
распределитель id обслуживает следующие уроки после загрузки. Старые эпизоды
без id траектории остаются такими. Независимые умы сохраняют отдельные пространства id.

## Приёмка кода

Использовать синтетические случаи без предметной области и strict learning.
Проверить:

1. Разметка назначается до регистрации; kwargs/сигнатуры сохранены.
2. Одинаковые повторные предъявления получают разные детерминированные id;
   штатное состояние траектории и потоки RNG не меняются.
3. Равные/разные timestamps, число независимых уроков больше окна, разные
   награды и повторы объектов дают глубину урока `0`. Отрицательный контроль
   без разметки различает прежнее поведение; смесь старых/новых изолирует новые.
4. Устойчивое состояние наяву неизменно; настоящий сон захватывает исходы и
   снимает labile-вклады без повторного захвата.
5. Сохранение/загрузка удерживает разметку, не меняет старые эпизоды и позволяет
   добавить новый независимый урок без коллизии.
6. Отсутствующая память, возврат `None`, заглушки без id/с запретом записи,
   наставническое обучение, оценённая обратная связь и неоценённая ветвь сохраняют контракты.
7. Проходят соответствующие body/onboarding/checkpoint-тесты и VC fast;
   независимый reviewer проверяет точный diff и доказательства.

## Приёмка поведения отделена

Новому классу кандидатов нужны собственный неизменный план и pins кода/стенда.
Согласованные курс, baseline, расписание, награды, seeds и критерии поведения
фиксируются. Контроль с отключённой разметкой обязан воспроизвести прежний
вариант с модельным временем до сравнения кандидатов. Формирование кандидата
повторяется с другим hash seed; проверяются загрузка в новом процессе и
продолжение обучения. Primary оценивается дважды с тем же RNG решений;
проверяется полнота таблиц и прежние критерии регрессий/неизвестного бюджета.
Заранее заданный дополнительный seed отчётный и не заменяет основного кандидата.

Успех тестов не подтверждает квалификацию и не разрешает принятие кандидата,
автоматическое создание документов или запись в ERP. Новый контракт не
ремонтирует и не воспроизводит прежние умы. Terminal-семантика, траектории
предпосылок роли, публичный API исходов ядра и квалификация — отдельные задачи.
