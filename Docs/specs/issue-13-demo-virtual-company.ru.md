## 1. Цель

Сотрудник — это ядро `Agent` (`AgentFactory.spawn_default`), которым управляет `BusinessAgentRuntime` сотрудника (`Demo/Virtual company/src/nowa_body/runtime.py`), подкласс runtime платформы (`src/mcp_body/runtime.py`, не меняется). Тот же runtime управляет Body Lab (`nowa_body/lab_session.py`, через `GuidedAgent`).

- Каждый такт решения передаёт время хоста `dt` (секунды) по контракту часов хоста.
- Дневные исходы (одобрения, отказы, уроки тела) остаются в лабильном слое.
- Стабильные параметры меняются только внутри `Agent.sleep()`.

## 2. Время хоста

`run_cycle(observations, now)` считает `dt` один раз за такт (`_host_dt`):

- `simulated_tick_seconds`, если хост его задал (сотрудник задаёт длину своего тика: это то, что хост называет тиком);
- иначе разница между `now` этого такта и предыдущего; первый такт — `0`.

Runtime передаёт `dt` в `step(..., decision_only=True, dt=dt)`, если у `step` объявлен параметр `dt`. Обёртка с `**kwargs` не считается. Иначе, а также если у агента нет `step`, вызывается `advance_time(dt)`. Запасной путь ядра через настенные часы не используется. `GuidedAgent.step` передаёт `dt` внутреннему агенту; принудительное действие лаборатории минует ум, но всё равно вызывает `advance_time(dt)`.

`expected_wake_interval_s` берётся из расписания сна (`SleepScheduler.expected_wake_interval_s`):

- ночное окно без триггера усталости: `max(24 ч, min_interval_s)`;
- триггер усталости задан: антидребезговый интервал (`min_interval_s`, в лаборатории `min_ticks_between_sleep × seconds_per_tick`) — самый короткий срок, через который может прийти сон.

С настройками сотрудника по умолчанию (окно 02–05, усталость 0.85, `min_interval_s` 3600) это `3600` с. Эксперименты с закупщиком шли без усталости и получали `86400` с. `tau_labile_s` — по умолчанию ядра (`1.0 ×` интервал).

`configure_plasticity(agent, scheduler)` записывает это значение сразу после создания сотрудника или агента лаборатории, до первого такта, и ещё раз после загрузки чекпойнта: чекпойнт мог сохранить старое. Ядро не меняется: `AgentFactory` строит агента с `PlasticityConfig` по умолчанию, поэтому ядро один раз при создании пишет «`expected_wake_interval_s` is unset»; запасные `3600` с не используются, потому что значение выставлено до первого такта. Передача конфига через `AgentConfig` убрала бы это предупреждение, но это изменение ядра, и оно оставлено для отдельного issue.

## 3. Сон

Когда `SleepScheduler.should_sleep` разрешает, runtime вызывает `Agent.sleep(cycles=sleep_cycles)` (по умолчанию 1). Это двухуровневый захват меток Go/NoGo и привычек, затем replay. `sleep_manager.sleep_cycle()` — только для агентов без `sleep` (заглушки лаборатории). `mark_slept` — только после успешного сна.

## 5. Инициализация и загрузка

- Сиды роли (`HippocampusSeeder`) пишут эпизоды гиппокампа — это состояние, а не стабильный уровень (см. [NOWA_Body_Lessons.ru.md](../../Demo/Virtual%20company/Docs/NOWA_Body_Lessons.ru.md) §5). Тесты в строгом режиме не дают `WakingLearningError` при создании и засеве.
- Чекпойнт ума (`save_mind` / `load_mind`, `AgentStorage`) загружается в строгом режиме, лабильная метка, записанная до `save_mind`, есть после `load_mind`.

## 6. Проверка

`Demo/Virtual company/tests/test_two_tier_host.py` с `NOWA_STRICT_LEARNING=1` и фикстурой, которая валит тест, если `WakingLearningError` была выброшена и перехвачена:

- ночное расписание → `86400`; усталость → антидребезговый интервал; тики лаборатории → `min_ticks × seconds_per_tick`; ядро получает значение, заглушку не трогаем;
- сотрудник, созданный со своим расписанием, имеет интервал до первого такта; агент лаборатории на ядре так же;
- четыре такта через 15 мин добавляют `3 × 900` с к `_host_clock_s`, `_dt_warning_sent` остаётся false; `simulated_tick_seconds` главнее часов такта;
- день тактов и урок не меняют `stable_fingerprint` и ставят лабильную метку; ночной сон меняет отпечаток и помечает урок `consolidated`;
- урок консолидируется один раз.


Эффект на закупщике (симулятор VC, жёсткий мир, 30 смоделированных дней, 5 зёрен): без адаптации проба на день 30 у зерна 21 — 81 (92 до #13); с адаптацией день 10 — 86 ± 6, день 30 — 83 ± 3, перерасход 0.

## 7. Вне объёма

- `Demo/Virtual company/src/nowa_sandbox/` (песочница закупок): её цикл обучения по-прежнему вызывает `sleep_manager.sleep_cycle()` и не передаёт `dt`. Отдельный issue.
- Runtime платформы `src/mcp_body/runtime.py`: он по-прежнему вызывает `step` без `dt` и спит через `sleep_manager.sleep_cycle()`. Сотрудник переопределяет `run_cycle` и такт решения в демо; исправление runtime платформы — изменение ядра, это решает мейнтейнер.
- Запасные пути ядра, лимиты replay, коэффициенты пластичности.
- Пробелы сохранения/загрузки ядра (#16).

## 8. Приёмка

1. Такты сотрудника и лаборатории передают `dt` хоста; нет предупреждения о запасном пути через настенные часы.
2. `expected_wake_interval_s` берётся из расписания до первого такта и после загрузки, а не из запасного значения ядра `3600` с.
3. Дневные исходы не меняют `stable_fingerprint`; `Agent.sleep()` меняет, по одному разу на урок.
4. Проходят `pytest -m "not slow"` в `Demo/Virtual company`. Когнитивное ядро не меняется.
