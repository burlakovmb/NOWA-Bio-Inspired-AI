## 2. Решение

### 2.1 `failure_log`

`FAILURE_LOG_RETAIN = 256`, рядом с `TICK_HISTORY_RETAIN`. `_record_failure` добавляет запись и оставляет последние 256
(`_trim_failure_log`). `Agent.restore_autonomous_state` так же обрезает восстановленный журнал, так что старый сейв с
длинным журналом возвращается последним хвостом. Журнал по-прежнему выгружается под ключом `failures`. Читатели проверяют,
есть ли недавний вид сбоя, — хвост его сохраняет.

### 2.2 Смерти одного тика

`SimulationRunner.tick` вызывает новый `_handle_agent_deaths(dead_ids)` вместо `_handle_agent_death` на каждый id:

- карта поколений строится один раз за тик; после каждой смерти умерший уходит из карты, а позиции после него в его
  поколении сдвигаются на одну — ровно то, что даёт перестройка без этого агента;
- `DeathRegistry.register_death(..., autosave=False)` записывает каждую памятку, а реестр пишется один раз в конце тика;
- строка журнала на каждую смерть (`_append_death_entry`, уже только дописывание), счётчики и удаление из `self.agents` —
  как раньше.

Памятки, строки журнала и итоговый файл реестра те же, что при обработке смертей по одной. `_handle_agent_death(agent_id)`
остаётся и передаёт работу пакетному методу. У `register_death` по умолчанию `autosave=True`, так что остальные вызовы не
меняются.

## 3. Тесты

- `tests/test_issue_28_failure_log.py` (3): журнал хранит последние `FAILURE_LOG_RETAIN` записей по порядку; короткий
  журнал сохраняется целиком; восстановление сейва с более длинным журналом оставляет его хвост.
- `Demo/Colony chinchillas/tests/test_issue_28_death_batch.py` (4): четыре смерти за тик, три из них в одном поколении,
  получают те же номера в поколении, что при перестройке по одной; реестр пишется один раз за тик, журнал перечисляет
  смерти по порядку; путь одной смерти не изменился; id, указанный дважды, считается дважды и регистрируется один раз,
  как раньше.

Тестам колонии нужен pygame; они запускались на Python 3.12.
