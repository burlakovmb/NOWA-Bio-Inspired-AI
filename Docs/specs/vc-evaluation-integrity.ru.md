# Целостность артефактов оценки VC

English: [vc-evaluation-integrity.en.md](vc-evaluation-integrity.en.md)

## Проблема и граница

Comparator не должен объявлять отсутствие регрессий после усечённого `zip`
или доверять отдельно сохранённой сводке бюджета. Проверять нужно и эталон,
и кандидата до подсчёта. Это контракт офлайн-артефакта; валидатору не нужны
сотрудник, ERP, доступ к файлам, сеть и внешняя LLM.

Реализация: `Demo/Virtual company/src/nowa_body/evaluation_contract.py`.
Публичная функция: `validate_evaluation(evaluation, *, probes_by_set, seeds,
ages, unknown_budget_groups, order_action)`. Возвращает кортеж: отображение строк
по ключам `(set, id, age_s, seed)` и пересчитанную сводку. Неверный вход вызывает
`ValueError`; частичный результат и вердикт приёмки не возвращаются.
Хеши фиксированных входов/плана/checkpoint/кода отдельно проверяет вызывающий.

## Полнота и привязка

- У каждого набора непустой фиксированный список проб с уникальными `id`
  и непустыми `group` и `expected_action`. Seeds и ages — непустые списки уникальных целых;
  логические значения не считаются целыми, ages неотрицательны.
- Строка результата содержит ровно `set`, `id`, `age_s`, `seed`, `group`,
  `expected`, `chosen`, `correct`. Идентификатор/действие/группа — непустые
  строки; `correct` — boolean; возраст и seed — целые, исключая booleans.
- Требуется полное декартово произведение фиксированных проб, возрастов и
  seeds. Пропущенные, повторные, лишние, неверно классифицированные и неизвестные
  ключи отклоняются. Изменённые `group` и `expected` отклоняются, а не принимаются
  после молчаливого пересчёта.
- Правильность вычисляется как `chosen == expected`; противоречивый флаг
  отклоняется. Незнакомое непустое выбранное действие считается неправильным,
  а не исчезает из знаменателя. Порядок строк не влияет на проверку.

## Сводка и сравнение

Для каждого набора пересчитываются `correct`, `total`, `unknown_budget_cases`,
`unknown_budget_false_order_intentions`, `by_age` и `by_group`. Ключи возрастов —
строки; значения возрастов/групп содержат `correct` и `total`. Группы неизвестного
бюджета задаются для каждого набора и должны существовать в фиксированных пробах.
Ошибочные намерения заказа считаются через `order_action`, без доверия группам
из сохранённых строк. Требуется точное совпадение со сводкой с учётом типов,
знаменателей и вложенных счётчиков. Boolean/float не являются целыми счётчиками.

Сравнивать проверенные отображения по полным ключам, без усечения позиционной
итерации. В эксперименте закупщика фиксированный набор содержит `567` старых и
`216` новых строк. Эти числа — вход эксперимента, а не константы валидатора.
Критерии нулевой регрессии и отсутствия роста бюджетных ошибок не меняются.
Свежие контроли остаются только отчётными; оценка не даёт профессиональной
квалификации.

Тесты должны охватывать пропуски/дубликаты, переименование всех старых строк
в свежие, подмену метаданных/ответов, неверные флаги, ложные бюджетные сводки,
ошибки знаменателей/типов счётчиков и корректную перестановку строк. Данные
только синтетические. Личные корпусы и локальные настройки в коммиты не входят.
